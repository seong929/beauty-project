# 고객 주문 배송 정보

고객 UI와 VM은 Riverpod를 사용한다. GetX 전환용 파일과 패키지는 제거했다.

- 결제 첫 화면의 **배송지 변경** 또는 상품 목록 아래 **주문 배송 정보 변경**에서 수령인·연락처·우편번호 검색·상세주소를 수정한다. 두 버튼 모두 이번 결제의 배송 정보 편집창을 연다. 변경은 이번 결제에만 적용되며 회원 기본 정보를 바꾸지 않는다. 저장하지 않고 닫으면 기존 배송 정보를 유지한다.
- 배송 요청사항 선택 또는 직접 입력도 결제 요청에 포함한다. `/orders_pay`가 주소·수령인·연락처·요청사항을 해당 주문에 저장한다.
- 구매 상세의 **배송 주소 변경**에서 열리는 주문 배송 정보 변경 화면에서는 이미 저장된 주문의 동일한 정보를 수정한다. `/customer_delivery_update`는 고객 소유 주문을 잠그고 출고 여부를 다시 확인한다.
- PENDING·PAID·PREPARING이며 배송 건이 없는 주문만 수정할 수 있다. SHIPPED·DELIVERED·취소·반품 주문 및 배송 건이 이미 등록된 주문은 서버에서도 변경을 거절한다.
- 기존 주소 전용 클라이언트가 새 필드를 생략하면 저장된 수령인·연락처·요청사항은 유지한다.

`database/migrations/20261030_order_shipping_details.sql`은 주문 테이블에 `shipping_recipient`, `shipping_phone`, `delivery_request`를 추가한다. 기존 주문의 주소·상태는 유지하고 수령인·연락처의 초기 값만 회원 정보로 채운다. 현재 연결된 DB에 적용했으며 신규 DB 정의에도 반영했다.

테스트는 우편번호 검색 결과와 상세주소 조합, 수령인·연락처 편집, 결제 전달, 저장 후 재조회, 출고 동시 변경 거절, 회원 기본 정보 보존을 검증한다. 실제 MySQL 검증은 `RUN_CUSTOMER_SHIPPING_MYSQL=1`로 실행하며 검증용 주문·포인트·재고 변경은 모두 롤백한다.
