# 고객 포인트 사용과 주문 취소

- 주문/결제의 `소담 포인트`에 사용할 정수 포인트를 입력하거나 `전액 사용`을 선택한다. 1P는 1원이며, 기존 보유 잔액과 주문 상품 금액 중 작은 값까지만 사용할 수 있다. 입력이 한도를 넘으면 한도로 조정한다.
- 선택한 포인트는 이번 결제의 Riverpod 상태로 관리한다. 단계 이동 중 값을 유지하고, 고객 변경·결제 화면 종료 시 초기화한다. 사용 포인트나 금액이 변경되면 결제 동의를 다시 확인한다.
- 포인트 조회에 실패하면 사용을 중단하고 다시 조회할 수 있다. 사용을 취소하면 포인트 없이 주문할 수 있다.
- `POST /orders_pay`의 선택 필드 `points_to_use`는 기본값 0이다. 서버는 고객 행을 잠근 뒤 잔액을 검증하고 DB 상품 가격으로 금액을 계산한다. 포인트 사용, 적립, 주문 생성, 재고 차감, 장바구니 정리는 같은 트랜잭션에 포함한다.
- 응답의 `total_amount`는 상품 금액, `used_points`는 사용 포인트, `payment_amount`는 포인트 차감 후 결제 금액이다. 적립은 `floor(payment_amount × 0.10)`이며 전액 포인트 결제는 적립하지 않는다. 새로 적립될 포인트를 이번 결제에 미리 사용할 수 없다.
- 주문별 사용 포인트는 `orders.used_points`에 저장한다. 포인트 내역은 `EARN`(적립), `USE`(사용), `CANCEL`(적립 회수), `RESTORE`(사용 복원)를 구분한다. 주문·유형별 고유키로 같은 취소의 중복 복원을 차단한다.
- 구매 상세의 `배송 주소 변경` 아래 `주문 취소` 버튼은 주문 전체를 취소한다. 확인창에서 승인한 후 `POST /orders_cancel?customer_id=...&order_id=...`를 호출한다. PAID 상태이며 배송 건이 없는 주문만 서버에서 취소할 수 있다. 서버는 주문 행을 잠그고 출고 여부를 다시 확인한다.
- 취소 시 사용 포인트를 먼저 돌려주고 해당 주문의 적립 포인트를 회수하며 재고와 출고 예약을 복구한다. 기존 정책대로 회수 가능한 잔액이 부족하면 전체 취소를 거절하고 롤백한다. 배송이 시작된 주문은 반품 신청을 사용한다.
- 주문 취소 이후 구매·배송·포인트·상품 조회를 갱신한다. 카드·계좌 승인과 환불은 기존처럼 외부 결제사에 연동되어 있지 않다.

## DB 적용

기존 포인트 내역 테이블 생성 마이그레이션 `20261030_customer_point_history.sql` 이후 `database/migrations/20261030_customer_point_usage.sql`을 적용한다. 현재 연결된 DB에는 적용했으며, 기존 고객 잔액·주문 상태·포인트 기록은 그대로 보존했다. 새 DB 정의는 `database/skin_project.sql`에 반영했다.

## 검증

백엔드의 고객 단위 테스트와 `RUN_CUSTOMER_POINTS_MYSQL=1 python -m unittest discover -s tests -p test_customer_points_mysql.py`로 부분 사용·전액 사용·실제 잔액·취소 복원·적립 회수·재고 복구·중복 취소 거절을 검증한다. 실제 DB 검증에서 만든 데이터는 마지막에 모두 롤백한다.

프런트엔드는 포인트 한도·단계 간 값 유지·순 결제 금액·적립 예상액·API 요청과 응답 검증·취소 확인창·중복 요청 방지·출고 동시 변경 거절을 테스트한다.
