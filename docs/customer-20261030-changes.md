# 고객 가입·결제 변경

## 회원가입과 개인정보

- `GET /customer_login_id_available?login_id=...`는 존재 여부만 확인한다. 고객 개인정보는 반환하지 않는다. 아이디를 바꾸면 중복 확인을 다시 해야 하며 가입 시 DB 고유키로 중복을 최종 검증한다.
- 가입 화면에 기존 Daum 우편번호 검색을 연결한다. 검색 주소와 상세주소를 합쳐 최대 500자로 저장하며 직접 입력도 지원한다.
- 선택 성별(M/F/OTHER/UNDISCLOSED)을 저장하며 로그인 프로필과 개인정보 수정에도 연결한다. 주소만 바꾸는 경우 기존 성별을 유지한다.
- 후속 요청에 따라 출생연도 입력·저장·응답을 API와 가입·수정 화면, 모델·요청 데이터에서 제거했다. 성별은 선택 항목이며 생략하면 기존 값을 보존한다.

## 수량·재고와 찜 제거

- 상세·장바구니의 수량 조절을 제거했다. 주문/결제 첫 단계의 주문 상품 정보에서 수량을 변경한다. 합계는 즉시 반영하며 최종 동의는 초기화한다.
- 고객 상품 조회의 판매 재고는 결제의 `NORMAL` 옵션에 맞춘다. 상품별 선택 수량을 합산해 재고 부족·품절·판매 중단·가격 미확인 상태를 표시한다. 선택하지 않은 상품 때문에 다른 상품의 결제를 막지 않는다.
- 재고 조회가 끝나지 않았거나 실패하면 다음 단계와 결제를 차단한다. 진입 시와 결제 직전에 재고를 다시 확인한다. 실제 동시 구매 경쟁은 기존 결제 API의 트랜잭션·재고 행 잠금으로 최종 검증한다.
- 찜 버튼·목록·메뉴와 Riverpod 찜 상태는 제거했다. 마이페이지 요약은 구매 주문 수·배송 중 건수로 표시한다.

## DB와 변경 주석

출생연도 추가 마이그레이션과 신규 DB 생성 스크립트의 출생연도 정의는 제거했다. 이미 적용된 DB의 기존 컬럼·값은 삭제하지 않으며, 고객 API는 해당 컬럼에 의존하지 않는다.

추가 중복 확인 API는 `backend/routers/customer/customer.py` 하단에 등록했다. 주요 수정 파일 하단의 `변경 내용(2026-10-30)` 주석으로 변경 목적을 표시했다.
